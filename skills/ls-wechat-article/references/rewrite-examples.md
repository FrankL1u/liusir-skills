# Rewrite Examples

Use these as few-shot rewrite patterns for Step 5A.

Keep the method.
Do not copy any specific persona wording.

## 1. 泛工具名 -> 具体工具名

Before:

```md
这类 AI 工具已经开始改变很多人的工作方式。
```

After:

```md
Claude Code 这类工具已经开始改变很多人的工作方式。
```

Rule:

- only replace when the draft already named a concrete tool
- if no concrete tool exists, keep the generic phrase out of the article or report it as a warning

## 2. 假设场景 -> 明确未亲测

Before:

```md
假设有一天，你把整个客服流程都交给模型处理。
```

After:

```md
如果只拿假设来解释，这里还没有一手验证。更稳的写法是先限定到你已经跑过的那一段客服流程。
```

Rule:

- do not invent a first-hand story
- when no real scene is available, convert the sentence into an explicit scope warning

## 3. 中性判断 -> 私人判断

Before:

```md
这个变化说明 AI 编程工具的效率提升很明显。
```

After:

```md
我后来才意识到，AI 编程工具真正抬高的不是写代码速度，而是我试错的胆子。
```

Rule:

- move from abstract conclusion to owned judgment
- keep the claim defensible

## 4. 报告腔 -> 聊天式知识掉落

Before:

```md
从宏观角度来看，这一趋势反映了组织协同方式的变化。
```

After:

```md
说白了，这不是一个工具升级问题，而是组织终于开始接受“先跑通，再规范”这套协同顺序。
```

Rule:

- keep the idea
- lower the distance
- avoid fake “conversational” filler

## 5. 直接说理 -> 先承认对立面，再推进

Before:

```md
大家不应该再用旧方法做内容了。
```

After:

```md
你继续用旧方法当然也能做，只是成本会越来越高。真正麻烦的不是它还能不能用，而是你会越来越晚发现它已经不划算了。
```

Rule:

- acknowledge the strongest objection first
- then push the reader toward the sharper conclusion

## 6. 结构过齐 -> 打破节奏

Before:

```md
有人在学习。有人在观望。有人在放弃。
```

After:

```md
有人已经开始学了。有人还在观望。也有人干脆停在那里，连自己到底在等什么都说不清。
```

Rule:

- break perfect symmetry
- let the last beat land harder than the first two
