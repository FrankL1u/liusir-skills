# Writing Guide

> Strong note copy feels useful at first glance, opinionated on second glance, and worth saving by the end.

## Core standard

The note should read like native posting copy, not like a shortened article.

Required qualities:

- one dominant angle
- short blocks
- visible payoff
- concrete wording
- spoken rhythm with real judgment
- platform-native pacing
- real-user texture instead of polished article texture
- sentence-driven expression instead of phrase stacking

## Drafting objective

Before writing, define one sentence:

`The note matters because _______.`

If that sentence is vague, the note will drift.

Good versions:

- `The note matters because most people are correcting the visible layer and missing the structural layer.`
- `The note matters because one small decision is causing repeated rework.`
- `The note matters because the obvious fix is not the useful fix.`

## Viral style objective

The note should not aim to look formal.  
It should aim to feel instantly readable, highly save-worthy, and naturally discussable.

Practical signals of strong platform fit:

- the first screen already contains a usable judgment
- the reader can quote one line after a quick skim
- the note gives one reusable rule, checklist, shortcut, or contrast
- the ending invites a real response, not empty engagement
- the language sounds experienced, not packaged

## First-screen rule

The first screen must do at least one of the following:

- name the mistake
- name the cost
- name the hidden bottleneck
- name the first useful fix
- name the judgment that reframes the problem

Weak first-screen moves:

- broad topic intros
- warmup sentences
- generic statements about popularity
- scene-setting with no tension

Useful first-screen patterns:

- `Most people compare the wrong thing.`
- `The visible problem is not the expensive problem.`
- `If this keeps failing, the missing piece is usually one layer deeper.`
- `I would not start from X. I would start from Y.`
- `The fast answer looks good. The durable answer starts elsewhere.`

## Paragraph rule

Paragraphs should be short enough to scan fast.

Practical default:

- one idea per paragraph
- most paragraphs `1-3` lines
- occasional longer block only when detail earns it

Avoid:

- stacked long paragraphs
- dense explanation before a concrete point appears
- transitions that only sound smooth but add no meaning

## Sentence rule

The note should be built from complete sentences or short natural paragraphs.

Use:

- lines that can stand as real spoken judgments
- short paragraphs that still carry subject, action, and consequence
- list structures only when each item is written as a sentence

Avoid:

- stacked noun phrases
- repeated half-sentences that only label ideas
- line-by-line fragments that read like presentation bullets
- chopping one idea into too many tiny pieces

## Rhythm rule

The note should feel like a good feed-native read:

- a strong line
- a short follow-up line
- a compact explanation block
- another sharp line before attention drops

Do not keep every paragraph the same length.  
Variation helps the note feel written, not assembled.

Good rhythm moves:

- one-line judgment
- two-line explanation
- one-line contrast
- one-line cost
- one-line question at the end
- a short paragraph that lands one full thought

Weak rhythm moves:

- five equal blocks in a row
- every line sounding like a heading
- every line ending in the same tone
- complete symmetry that makes the note feel templated

## Body rule

Every body block should carry one job:

- diagnose
- reframe
- explain
- instruct
- compare
- prove

If a block does not change the reader's understanding or action, cut it.

## Save rule

A save-worthy note gives the reader something reusable:

- a sharper framing
- a first step
- a decision rule
- a checklist
- a contrast that clarifies choice

Writing that feels polished but leaves nothing reusable should be treated as weak.

## Comment rule

Comment-worthy copy opens a real branch of discussion.

Use endings like:

- `Which layer breaks first for you now?`
- `Which side of this decision are you still stuck on?`
- `If one part deserves a deeper breakdown, which part is it?`

Avoid:

- direct requests for likes or follows
- fake-open questions with no real trade-off
- engagement bait that does not match the note body

## Judgment rule

The note should sound like someone who has seen the problem enough times to stop speaking vaguely.

Use:

- clear judgments
- concrete costs
- visible trade-offs
- short cause-and-effect statements

Avoid:

- empty balance
- abstract agreement language
- praise without downside
- slogans disguised as insight

## Emoji rule

Emoji can be used as scan anchors, not as decoration spam.

Use:

- `2-6` emoji in a standard note
- emoji at title level, before a key shift, inside a numbered body move, or at the ending question when it improves scanning
- emoji with semantic value, such as warning, comparison, checklist, or result
- let emojis create visual landmarks across the note instead of clustering them only in the title

Examples:

- `别先比功能，先看交接成本 ⚠️`
- `真正该看的有 3 层：输入、结果、回看路径 👇`
- `先看输入能不能平移，再看结果能不能复用 ✅`
- `你现在最容易卡住的是哪一层？🤔`

Avoid:

- one emoji per line
- pure cute decoration with no reading function
- repeated identical emoji stacks
- emojis that make the note look promotional instead of useful
- all emojis concentrated in the title while the body stays visually flat

## Authenticity rule

Native notes should feel grounded in real observation, real use, or real judgment.

Use:

- visible trade-offs
- concrete failure modes
- language that matches lived use
- claims that the body can actually support

Avoid:

- exaggerated promises
- fake certainty
- claims that oversell the outcome
- wording that makes the note feel copied from ad copy

## Source-article derivation rule

In Step 4, write a source article first and then derive the note from it:

- keep one dominant insight
- cut secondary branches
- convert explanation into a faster sequence
- keep enough structure for visual slicing
- rewrite, do not compress sentence by sentence
- replace article headings with native note pacing
- keep the strongest tension line and throw away most setup lines

The note should feel born for the platform, not reduced from another format.

## CTA rule

The ending should trigger one next move:

- reply with the main bottleneck
- choose between two directions
- ask for the next breakdown

Avoid:

- generic support language
- multiple asks in one ending
- empty engagement bait

## Hashtag rule

Hashtags should improve discovery fit, not look stuffed.

Use:

- `3-6` hashtags at the bottom
- tags that match the note's real scenario, task, or audience
- one current hot-topic tag only when the body actually belongs in that topic

Avoid:

- irrelevant hot tags
- long tag walls
- repeating the exact same meaning with slightly different wording
- tags that promise a topic the body does not deliver

## Anti-patterns

- article-like opening
- markdown heading dependency in the final note
- phrase-stacking that reads like slide bullets
- general trend commentary with no judgment
- long explanation before the conclusion
- repeated abstractions
- broad productivity vocabulary
- `first, second, third` scaffolding with no added meaning
- headings that only rephrase the title
- excessive emoji styling
- asking for saves or follows directly
