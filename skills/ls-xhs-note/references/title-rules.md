# Title, Hook, Tag, and CTA Rules

Use this file in Step 5.

The goal is to improve click quality, scan speed, and save intent without sliding into empty noise.

## Extraction order

Before writing title and hook options, identify:

- visible problem
- real fix
- payoff
- contrast pair
- one proof point

Use these roles to generate posting copy.

## Title rules

### Hard rules

- Prefer `16-24` Chinese characters when possible
- Lead with tension, payoff, contradiction, or a direct decision
- Avoid generic topic openers
- Avoid repeating one abstract noun multiple times
- Avoid restating a body heading unchanged

### Required title directions

Generate at least three directions:

1. tension
2. payoff
3. contradiction

### Tension titles

Use when the note starts from a repeated mistake or a hidden cost.

Examples:

- `为什么多数工作流越搭越乱`
- `你以为在补效率，其实一直在补返工`

### Payoff titles

Use when the note gives a clear first fix or decision rule.

Examples:

- `先把输入和交付物定下来，再谈提效`
- `如果只改一件事，先把回看路径固定下来`

### Contradiction titles

Use when the note contains a strong visible-vs-real contrast.

Examples:

- `你以为问题在工具，其实关键在交接设计`
- `你以为卡在速度，其实卡在结果定义`

## Hook rules

### Hard rules

- the first `1-2` lines must add value beyond the title
- the hook should sound spoken and direct
- the hook should reveal tension fast
- the hook should not paste a long body sentence unchanged

### Reliable hook moves

- point out the mistaken assumption
- point out the hidden cost
- point out the first useful fix
- point out the real bottleneck

Examples:

- `多数返工不是做得慢，是一开始没有把结果说清楚。`
- `先别继续堆流程，先把输入、结果和回看路径固定下来。`
- `问题不在工具数量，问题在交接层没有设计。`

## Hashtag rules

- use `3-8` hashtags
- mix broad discovery tags and scenario tags
- keep tags tied to the body
- prefer intention, workflow, role, or scenario language

Avoid:

- repeated title fragments
- random English filler
- tags unsupported by the note

## CTA rules

- ask for one response only
- keep the ask close to the note's decision point
- prefer prompts that extend the conversation naturally

Examples:

- `更容易卡住的环节，是输入、结果，还是回看？`
- `下一轮更值得展开的方向，是框架、流程，还是改稿？`
- `如果要补一张图，最需要可视化的是哪一步？`

## Comment seed rules

Comment seeds should:

- be short
- create a low-friction reply path
- continue the core tension

Good patterns:

- binary choice
- single bottleneck question
- one missing-step question

## First-screen copy rules

First-screen copy should:

- keep one dominant claim
- stay shorter than the body title
- avoid dense explanation
- work as a first-slide promise

Useful first-screen copy directions:

- pain statement
- contradiction
- simple decision rule
- one-line promise

## De-AI pass

- cut polished filler
- replace broad claims with one real consequence
- shorten repeated abstractions
- prefer sharper spoken lines over overly balanced prose
