# Style Selection

Choose preset from content shape first.  
Open `style` and `layout` only when the preset needs an explicit override.

| Content shape | Primary preset | Secondary preset | Why |
|---------------|----------------|------------------|-----|
| strong judgment, sharp contradiction | `bold-statement` | `poster` | strongest first-screen pressure with minimum noise |
| procedural explanation, step flow | `tutorial` | `blueprint-stack` | preserves sequence and makes layered logic readable |
| knowledge-heavy notes, tool stacks, framework notes | `blueprint-stack` | `knowledge-card` | best for structured information with engineering clarity |
| deep system breakdown, layered framework, production experience | `deep-dive-blueprint` | `study-guide` | supports more explanation without losing technical sharpness |
| comparison, versus framing, skill battle, tool trade-off | `doodle-showdown` | `editorial` | keeps comparison lively while preserving one clear choice axis |
| friendly explainer, mascot-led teaching, approachable technical notes | `mascot-lab` | `tutorial` | softens complex ideas without losing structure |
| ranked points, lists, pitfall collections, recommendations | `mascot-checklist` | `checklist` | easiest to scan, save, and share as a practical list |

## Selection rules

- choose a preset before touching `style` or `layout`
- treat `style` and `layout` as advanced overrides, not the first decision
- downgrade density if the copy becomes unreadable
- use `bold-statement` or `poster` only when one claim can carry the series
- use blueprint presets when the note depends on layered explanation
- use mascot presets when the topic needs more warmth and approachability
- use doodle presets when comparison should feel lighter and more shareable

## Default rule

- default to `blueprint-stack` for knowledge-first notes
- default to `bold-statement` for judgment-first notes
- default to `mascot-checklist` for tool lists and recommendation notes
