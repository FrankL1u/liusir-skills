# Platform Constraints

## Core constraints

- one note should carry one dominant angle
- the first screen should create tension, payoff, or a clear decision
- the body should stay fast to scan
- the copy should sound native to posting, not native to essays
- images should package the point, not rescue weak writing

## Length constraints

- compact note: `250-450` Chinese characters
- standard note: `450-800` Chinese characters
- dense note: `800-1100` Chinese characters

Longer copy is allowed only when the note remains highly scannable.

## Paragraph constraints

- prefer `1-3` lines per paragraph
- avoid stacking multiple long paragraphs without a strong reason
- keep each paragraph focused on one job

## Structure constraints

- title first
- hook immediately after the title
- body blocks should move quickly
- CTA should ask for one next move
- hashtags should remain compact and relevant

## Tone constraints

- direct
- useful
- judgment-heavy when needed
- concrete
- lightly spoken, not sloppy

Avoid:

- formal article narration
- academic exposition
- generic self-help tone
- hollow intensity

## Content constraints

- one dominant insight only
- one core promise only
- one main contrast only
- cut side branches that dilute the angle

## Visual coordination constraints

- body blocks should be easy to split into slide units
- if a dedicated first-screen page is used, it should carry one promise
- content slides should carry one message per slide
- ending slide should stay lighter than the content slides

## Tag constraints

- do not use irrelevant discovery tags
- do not flood the ending with hashtags
- keep tag intent aligned with the note body

## CTA constraints

- no multi-step ask
- no generic attention requests
- no ending that repeats the title without a new move

## Red flags

- reads like a blog post
- background arrives before value
- every paragraph is the same size
- the note explains more than it helps
- the images need to carry the whole meaning alone
